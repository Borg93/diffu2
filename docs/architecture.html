≠ What's new vs DiffusionPen / DiffBrush

Those are the old lineage — U-Net + SD-1.5 4-ch VAE + DDPM, no REPA, no DINO, no flow-matching, no CFG. Diffu is a generation newer on every axis.

🧩 The cast + exact sizes

Trainable ≈ the 900M backbone + small heads. Frozen ❄️ = VAE, DINOv3, HTR.

❄️ frozen · 16-ch f8

Qwen-Image VAE

[B,3,128,W] → [B,16,16,W/8]

Why 16-ch: SD's 4-ch latent smears the strokes that separate a / ä / å; 16-ch + a text-tuned decoder preserves diacritics. A recon-CER gate (diffu-vae-gate) checks before training that the latent keeps legibility.

✅ CNN trained

Glyph content encoder

Unifont 32px → ResNet18 → [B, w_t, 1024]

Why: Unifont covers all Unicode → any glyph representable by construction. Keeps the spatial map (no avgpool) so column j ≈ image column j.

❄️ DINOv3 · ✅ pool

Style encoder

ViT-L/16 → [B,201,1024] → resampler → [B,64,1024] → pool → [B,1024]

Two poolings: 64 learned queries cross-attend DINO patches (variable→fixed), then 1 learned query → one vector. Pooled-only so it can't copy the reference's letters.

✅ ~900M · trained from scratch · SD3.5

SD3 MMDiT backbone

dim 1024 · 24 layers · 16 heads · patch 2 · SD3.5 qk_norm

Why a transformer + RoPE: joint attention fuses text+image in one stream; relative 2D-RoPE handles variable line width (the absolute table was the overflow cause). SD3.5 qk_norm (Q/K RMSNorm) for training stability; dual-attention wired but off.

no params

Rectified flow + scheduler

x_t=(1−t)x0+t·ε · predict v=ε−x0

Why velocity: the constant slope of the straight noise↔clean line → stable training. ~24 Euler steps at sampling.

✅ tiny · training-only

REPA projector

3-layer SiLU MLP (1024→1024), cosine-align layer 8 to DINO; off after 40% of steps

Why: a representation head-start — the brain's mid layer is pushed to "look like" DINO's view of the target → faster convergence, finer detail.

⊕ The attention mechanism (inside one of the 24 blocks)

Each block runs one joint self-attention over [image tokens ; text tokens] — the "MM" in MMDiT. Text directly co-shapes the pixels every layer.

  • 1. Project Q,K,V. Each token → query/key/value via W ∈ ℝ1024×1024 (image & text use separate projections).
  • 2. Split heads. 1024 = 16 heads × 64 → [B, 16, seq, 64]. Each head tracks a different relationship (baseline, spacing, slant…).
  • 3. Rotate. 2D-RoPE on image Q/K (row+col freqs); content tokens share the column rotation so token j ≈ image column j.
  • 4. Concatenate image+text along the sequence → one stream.
  • 5. Attend. softmax(QKᵀ/√64)·V (FlashAttention). Every patch sees every patch and every text token.
  • 6. AdaLN (separate): the pooled style vector + timestep set each block's LayerNorm scale/shift — a global knob, not part of attention.

Why joint, not cross-attention? content/style/image interact in one shared attention, so the requested text shapes the ink at every layer instead of via a side channel.

# one MMDiT block, joint attention img tokens [B, 512, 1024] # =h_t·w_t: 512 at 1024 px, no cap txt tokens [B, w_t, 1024] # content only (style is pooled) │ to_q/to_k/to_v + add_q/k/v_proj ▼ reshape → 16 heads × 64 Q,K,V [B,16,seq,64] │ 2D-RoPE on image Q/K; content Q/K share the column freqs ▼ concat [img ; txt] attn = softmax(Q·Kᵀ / √64) · V ▼ split back → image stream continues AdaLN scale/shift ← (pooled[1024] + t_emb)

⇄ REPA ↔ DINO — the representation head-start, exactly

Don't make the brain learn visual structure from scratch — force a mid layer (8) to look like a frozen DINO's view of the target. Faster convergence + finer detail (diacritics).

DiT side (student) DINO side (teacher, frozen ❄️) hook block[8] → img hidden [B,N,1024] target line, native size → ImageNet-norm │ repa_proj = 3-layer SiLU MLP │ frozen DINOv3 → keep the patch tokens ▼ ▼ reshape [B,1024,H/16,W/16] proj [B,N,1024] ◄── cosine ──► 16-px patches = the DiT grid [B,1024,h_t,w_t] ▼ flatten row-major target [B,N,1024] L_repa = mean( 1 − cos( L2(proj) , L2(target) ) ) · 0.5 # per-token, NOT pooled
  • Row-major on both sides → DiT token i ↔ DINO patch i (same spatial location). That correspondence is the whole point; the old mean-pooled version threw it away.
  • Cosine, not MSE — aligns direction, not magnitude (the modern best-practice; confirmed by HASTE & HAE).
  • Training-only; only the flow term is logged (val-comparable). A guard raises if the hidden state isn't differentiable (so REPA trains the backbone, not just the head).

⚠️ Best-practice gap (HASTE, "REPA Works Until It Doesn't"): REPA helps early but erases high-frequency detail late — its gradient turns against the denoiser's. The code terminates it early: weight 0.5 for the first 40% of steps, then off (repa_stop_frac=0.4). Core config (cosine, layer 8, weight 0.5, DINOv3-L, per-token) is otherwise textbook-correct.

↑ CFG — the legibility lever

  • Training prereq: --cond/--text-dropout randomly zero the conditioning, so the model learns an unconditional mode too.
  • Each sampling step runs the brain twice: normal (v_cond) and with content zeroed, style kept (v_uncond).
  • Combine: v = v_uncond + s·(v_cond − v_uncond), default s = 5.
  • Why: (v_cond − v_uncond) is the direction that depends on this text; s>1 exaggerates text-following.
  • Canvas mode: a second knob, style guidance (--style-cfg-scale), contrasts with/without the reference — trained with --ref-dropout.
  • Cost: 2× forwards/step. Best-practice: lower scale on an interval t∈[0.3,0.7] once REPA-aligned (high s everywhere over-saturates to white).

↔ Auto-width & length control — the model's biggest quirk

The model has no internal length control — trained only on tight crops, it learned to fill the canvas. Too wide → it overflows (repeats glyphs); too tight → it crams. So we must hand it the right width: width = natural_width(text) × 0.45 (≈24 px/char at 128 px), then ink-crop the tail.

CER sweep over px/char (64 px era) — monotonic: tighter is strictly better down to the corpus density (15 px/char), no cramming.

  • The data: real corpus density is ~15 px/char at 64 px (measured image_w ÷ len over 2000 lines).
  • The fix: a one-liner — _WIDTH_BIAS = 0.55 (≈15 px/char at 64 px) → ~11× CER drop vs the old 30. The bias is height-coupled: at 128 px it is 0.45 (≈24 px/char).
  • Why overflow: we removed the absolute position table (good — variable width via RoPE), but the model never learned to stop; the fill_ratio signal is too weak (buried in the pooled vector). White-pad training alone didn't fix it.
  • Length control for the next models: --glyph-pad — glyph tokens only over the line's ink extent, blank after → "write N chars and stop" (implemented, not trained yet).

∿ Sampling steps — integrating the flow ODE

Generation integrates an ODE from t=1→0 with a Euler scheduler; each step predicts v̂ and nudges toward clean. Inference-only (training uses one random t) — change freely, no retraining.

CER vs steps (width fixed) — roughly flat, mild best ~24–40, noise past that. Cost is linear (8→0.4s, 60→2.5s/line).

  • More steps polish render quality (smoother strokes), NOT legibility. The recognizer reads ~24-step and ~40-step output about the same.
  • Takeaway: default ~24 (best CER/speed), 40 for cleanest strokes, never 60.
  • Contrast: the width knob is ~10× more impactful than steps (0.41→0.037 vs ~0.09→0.05).
